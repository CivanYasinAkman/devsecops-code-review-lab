# Zafiyet ve Kaynak Kod Eşleme Tablosu (Root Cause Analysis)

Önceki sızma testi (Pentest) projesinde tespit edilip sömürülen dinamik zafiyetlerin ve ek analiz bulgularının kaynak kod üzerindeki statik karşılıkları aşağıda haritalandırılmıştır:

| No | Zafiyet Türü | PoC / Sömürü Yöntemi (Saldırgan Gözü) | Dosya Yolu | İlgili Fonksiyon / Kök Neden (Geliştirici Gözü) |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Broken Access Control** (Scoreboard) | `/#/score-board` URL'sine direkt gidilerek gizli skor tablosuna yetkisiz erişim sağlandı. | `frontend/src/app/app.routing.ts` | Routing (yönlendirme) tanımlamalarında Scoreboard yolu için herhangi bir `AuthGuard` (yetki kontrolü) mekanizması eklenmemiş. |
| **2** | **SQL Injection** (Login) | Email kutusuna `' OR 1=1 --` yazılarak şifresiz Admin girişi yapıldı. | `routes/login.ts` | `models.sequelize.query(...)` içinde parametreli sorgu kullanılmamış, `req.body.email` doğrudan string birleştirme ile SQL komutuna eklenmiş. |
| **3** | **DOM XSS** (Search) | Arama kutusuna `<iframe src="javascript:alert(1)">` yazılarak zararlı JS çalıştırıldı. | `frontend/src/app/search-result/search-result.component.ts` | Kullanıcı girdisi, Angular'ın `DomSanitizer.bypassSecurityTrustHtml()` fonksiyonu kullanılarak zorla güvenli kabul edilip doğrudan DOM'a basılmış. |
| **4** | **IDOR / BOLA** (Basket) | HTTP isteğindeki `/rest/basket/6` yolu `1` yapılarak başka kullanıcının sepeti görüldü. | `routes/baskets.ts` | `router.get('/rest/basket/:id')` endpoint'inde, istenen `id`'nin aktif oturumdaki (`req.currentUser`) kullanıcıya ait olup olmadığı backend tarafında kontrol edilmiyor. |
| **5** | **Brute Force** (Login) | Burp Intruder ile hız sınırı olmadan binlerce şifre denemesi yapılarak hesap ele geçirildi. | `routes/login.ts` | Endpoint üzerinde `express-rate-limit` gibi bir hız sınırlandırma middleware'i veya hesabı geçici kilitleyen (account lockout) bir mekanizma bulunmuyor. |
| **6** | **CSRF** (Password Change) | Sahte hediye sayfası üzerinden `GET /rest/user/change-password?new=hacked123` isteği tetiklendi. | `routes/changePassword.ts` | Şifre değiştirme işlemi güvensiz olan `req.query` (GET) üzerinden alınıyor ve istekte hiçbir Anti-CSRF Token doğrulaması yapılmıyor. |
| **7** | **Vulnerable Components** (LFI / Null Byte) | `/ftp/package.json.bak%2500.md` ile uzantı filtresi aşıldı ve hassas dosya okundu. | `routes/fileServer.ts` | `req.params.file` değişkeni okunurken Null Byte (`%00`) temizliği yapılmıyor. Sadece basit bir `.includes()` veya `endsWith()` kontrolü ile uzantı doğrulaması atlatılabiliyor. |
| **8** | **Mass Assignment** (Admin Register) | Kayıt (Register) isteğinin Body kısmına `"role":"admin"` eklenerek admin hesabı açıldı. | `routes/register.ts` | `models.User.create(req.body)` fonksiyonu, gelen tüm JSON anahtarlarını filtrelemeden (whitelist olmadan) doğrudan veritabanı modeline atıyor. |
| **9** | **XXE** (B2B Order Processing) | B2B sipariş uç noktasına `<!ENTITY xxe SYSTEM "file:///etc/passwd">` içeren XML gönderildi. | `routes/b2bOrder.ts` | XML ayrıştırıcısı (parser) `libxmljs.parseXmlString(req.body, { noent: true })` ayarı ile çalıştırılıyor. `noent: true` parametresi dış varlıkların (external entities) çözümlenmesine izin veriyor. |
| **10** | **Open Redirect** (GitHub Yönlendirmesi) | `/redirect?to=https://evil.com` adresiyle kullanıcı sahte bir siteye yönlendirildi. | `routes/redirect.ts` | `res.redirect(req.query.to)` fonksiyonu çalışmadan önce, `to` parametresinin şirket içi güvenilir bir domain olup olmadığını kontrol eden bir `whitelist` bulunmuyor. |
